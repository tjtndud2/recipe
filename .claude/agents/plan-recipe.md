# 프로젝트: 냉장고 파먹기 (자취생 요리 게임 웹앱)

오늘 1일 해커톤에서 혼자 만들고 16:00까지 Vercel에 배포해야 하는 웹 게임이야. 나는 초보 개발자라서 코드를 이해하기 쉽게 작성하고, 주요 부분에 한국어 주석을 달아줘. 기능을 늘리지 말고 아래 범위만 확실하게 동작하게 만드는 것이 최우선이야.

## 기술 스택 (변경 불가)
- Next.js (App Router, TypeScript) + Tailwind CSS
- 배포: Vercel
- DB: Supabase (랭킹 저장용)
- AI: Next.js Route Handler(app/api/recipe/route.ts)에서 Claude API 호출
- 환경 변수: ANTHROPIC_API_KEY, NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY
  - ANTHROPIC_API_KEY는 서버 코드에서만 사용하고 클라이언트에 절대 노출하지 마
- TypeScript 타입 오류가 있으면 Vercel 빌드가 실패하니, any 남발 없이 타입을 명확히 정의하고 단계마다 npm run build가 통과하는지 확인해줘

## 게임 개요
플레이어는 자취생이 되어 냉장고 속 재료로 요리를 3번 만든다. 유통기한이 임박한 재료를 잘 활용하고 미션 조건을 만족할수록 높은 점수를 받는다. 한 판은 2분 안에 끝나야 한다.

## 화면 구성 (3개 페이지)
1. 시작 화면 (/)
   - 게임 제목, 한 줄 소개("남은 재료, 버리지 말고 요리하자!")
   - "게임 시작" 버튼, "빠른 시연" 버튼, 랭킹 TOP 10
2. 게임 화면 (/play)
   - 상단: 라운드(1/3), 현재 점수, 이번 라운드 미션 카드
   - 냉장고: 재료가 이모지 + 이름 + 남은 유통기한(D-2 등)으로 표시
   - 유통기한 D-1 이하는 빨간 테두리와 흔들리는 애니메이션
   - 재료를 클릭하면 아래 냄비에 담기고, 다시 누르면 빠짐 (드래그 없이 클릭만)
   - 냄비에 2개 이상 담기면 "요리하기" 버튼 활성화
   - 요리 중: 냄비가 끓는 애니메이션 + "요리 중..." (AI 응답 대기)
   - 결과 모달: 요리 이름, 이모지, 조리 순서, 셰프 한마디, 점수 계산 내역, 별점, "다음 라운드" 버튼
3. 결과 화면 (/result)
   - 총점, 만든 요리 3개 요약, 버려진(썩은) 재료 수
   - 닉네임 입력 후 "랭킹 등록" 버튼 → Supabase에 저장 → 랭킹 표시
   - "다시 하기" 버튼

## 게임 규칙
- 시작 시 재료 풀(data/ingredients.ts, 25개)에서 9개를 랜덤으로 냉장고에 넣고, 각 재료에 유통기한 D-1 ~ D-5를 랜덤 부여
- 미션 풀(data/missions.ts, 8개)에서 라운드마다 하나씩 랜덤 제시
  - 예: "시험기간 - 10분 안에, 전자레인지만", "월급날 전 - 추가 구매 재료 0개", "다이어트 중 - 튀기지 않는 요리"
- 라운드가 끝날 때마다 남은 재료의 유통기한이 1씩 줄어들고, 사용한 재료는 사라짐
- 유통기한이 0 미만이 되면 썩은 상태(🦠)로 바뀌고 선택 불가

## 점수 계산 (AI가 아니라 코드에서 계산)
- 사용한 재료 1개당 +10점
- 유통기한 D-1 이하 재료 사용 시 1개당 +20점 추가
- 추가 구매 재료(missing) 1개당 -10점
- 미션 달성 시 +30점 (AI 응답의 mission_success 사용)
- 게임 종료 시 썩은 재료 1개당 -15점
- 라운드 별점: 80점 이상 ⭐⭐⭐, 50점 이상 ⭐⭐, 그 외 ⭐

## AI 연동 (app/api/recipe/route.ts)
- 요청: 선택한 재료(이름, 남은 유통기한), 미션 조건, 이전 라운드 요리 이름 목록
- 선택한 재료로 만들 수 있는 요리 1개를 아래 JSON으로만 답하게 할 것:
  {
    "name": string,
    "emoji": string,
    "time_minutes": number,
    "used_ingredients": string[],
    "missing_ingredients": string[],   // 최대 2개
    "mission_success": boolean,
    "mission_comment": string,
    "steps": string[],                 // 최대 5단계, 구체적인 시간과 양 포함
    "chef_comment": string             // 재밌는 한마디
  }
- 시스템 프롬프트 규칙:
  - 1인분, 요리 초보도 따라 할 수 있는 수준
  - 소금, 간장, 설탕, 식용유는 기본으로 있다고 가정
  - 미션의 조리도구·시간 조건을 지키지 못하면 mission_success는 false
  - 이상한 재료 조합이어도 먹을 수 있는 요리를 창의적으로 만들 것
  - 육류·계란은 완전히 익히라는 안내 포함, 위험한 조리법 금지
  - JSON 외 텍스트나 코드블록 기호 금지
- 응답의 ```json 기호를 제거한 뒤 JSON.parse, try/catch로 감싸기
- 응답 타입을 TypeScript interface로 정의하고 필드 검증

## 실패 대비 (가장 중요)
- AI 호출이 실패하거나 8초 이상 걸리면 data/mockRecipes.ts(12개)에서 선택 재료와 가장 많이 겹치는 레시피를 반환. 사용자 화면에서는 멈추지 않고 자연스럽게 결과가 나와야 함
- ANTHROPIC_API_KEY가 없어도 앱이 에러 없이 대체 데이터로 동작해야 함
- Supabase 연결이 실패해도 게임은 끝까지 진행되고, 랭킹 영역에만 "랭킹을 불러올 수 없어요" 표시
- "빠른 시연" 버튼: 고정된 재료 9개(임박 재료 3개 포함)와 고정 미션 3개로 시작해서 매번 같은 흐름으로 시연 가능하게

## Supabase
- leaderboard 테이블 생성 SQL을 알려줘: id, nickname(최대 10자), score, created_at
- 익명 사용자가 insert와 select만 할 수 있도록 RLS 정책 SQL도 함께 알려줘
- 닉네임은 공백 제거 후 1~10자만 허용

## 디자인
- 파스텔톤, 둥근 모서리, 큼직한 이모지, 모바일에서도 보기 좋게
- 재료 담기, 점수 획득 시 간단한 애니메이션 (Tailwind 기본 기능 위주로, 추가 라이브러리 최소화)

## 작업 순서
단계별로 진행하고, 각 단계가 끝날 때마다 npm run build 통과를 확인해줘.
1. Next.js 프로젝트 세팅 → 기본 페이지만 있는 상태로 Vercel 첫 배포 방법 안내
2. 데이터 파일(재료, 미션, 대체 레시피)과 타입 정의
3. 게임 화면: 재료 선택, 대체 데이터로 결과까지 동작, 점수 계산, 3라운드 진행, 결과 화면
4. Claude API 연동 (실패 시 대체 데이터로 자동 전환)
5. Supabase 랭킹 등록과 조회
6. 빠른 시연 모드, 애니메이션과 디자인 다듬기
7. Vercel 환경 변수 등록과 재배포 체크리스트 안내
